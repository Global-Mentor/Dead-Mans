# Справочник карт и локаций Hunt

Карты, локации и их игровые названия хранятся в PostgreSQL. Это общий контент для
вопросов, сайта, OBS и Twitch, а не переводы интерфейса. Подписи элементов управления
остаются в i18next. Отдельного списка названий во frontend нет.

## Модель и жизненный цикл

- `hunt_maps`: постоянный UUID, уникальный код карты клиента, `is_enabled`.
- `hunt_locations`: постоянный UUID, FK `map_id`, код локации, `is_enabled`.
  Код уникален внутри карты. Локация однозначно определяет карту.
- `hunt_map_translations`: PK `(map_id, locale)`, игровое `name`.
- `hunt_location_translations`: PK `(location_id, locale)`, игровое `name`.

Поддерживаются `en`, `ru`, `uk`, `pl`. Названия не являются идентификаторами:
исправление перевода не меняет ссылки на локацию. FK используют `Restrict`.
Недоступный контент отключается; удаление игры не должно удалять этот справочник.
Временная ротация карт в Hunt не означает отключение карты для викторины.

Миграция `20261102173557_AddHuntLocationCatalog` создаёт таблицы и добавляет четыре
карты, 64 локации и 272 локализованных названия. Данные зафиксированы в её
[части с наполнением](../../backend/Data/Migrations/AddHuntLocationCatalog.Seed.cs).
Миграция не читает сеть, игровые файлы или изменяемый runtime-каталог. Повторный
запуск приложения не перезаписывает справочник. Новые названия и исправления
добавляются следующими миграциями с сохранением UUID; применённая миграция не меняется.

Справочник используется в [викторине по скриншотам](screenshot-quiz.md):

- сервер проверяет доступность карты и локации и выбирает неправильные ответы
  по `map_id`, исключая правильную локацию;
- сайт и OBS сопоставляют язык интерфейса с поддерживаемой локалью; отсутствие
  ожидаемого перевода не заменяется машинным переводом;
- опубликованный вопрос сохраняет выбранные локации и снимки названий для всех
  поддерживаемых языков; показанный порядок вариантов общий для сайта, OBS и Twitch;
- история читает снимок вопроса, а не актуальное название из справочника.

## Выбор следующего скриншота

Визуальные вопросы используют существующее правило автоматического выбора обычной
викторины. Единица выбора и учёта показов - отдельный вопрос со скриншотом,
а не локация. Несколько скриншотов одной локации допустимы в одной игре,
в том числе подряд. Ограничения или понижение приоритета по локации не применяются.

Алгоритм для выбранного формата:

1. Оставить включённые, не удалённые вопросы, выбранные для игры, которые ещё
   не запускались в этой игре.
2. Выбрать минимальное число запусков вопроса за всю историю игр. Вопросы,
   которые ни разу не запускались, имеют счётчик `0`.
3. Среди них оставить вопросы с максимальным `PrioritySnapshot`.
4. При равенстве выбрать случайный вопрос.

Счётчик соответствует существующему запросу по `GameQuizQuestionSessions`:
учитывается факт запуска, без фильтра по статусу сессии или числу ответивших.
Один конкретный скриншот не повторяется в пределах игры. Выбор ведущим конкретного
вопроса обходит автоматическое ранжирование, сохраняя проверки доступности.

Прямой запуск и запуск через Twitch должны применять одно правило ранжирования.
Twitch дополнительно сохраняет свои проверки возможности публикации и исключает
уже зарезервированные вопросы. Фильтр формата применяется до ранжирования:
кнопка следующего скриншота не выбирает текстовый вопрос и наоборот.

## Источники и точность названий

Проверено 2026-11-02. Первичный источник написания: поставляемые Crytek файлы
локализации установленного клиента **2.9.1.39**, Steam build **25749579**.
Это идентифицированный снимок клиента, а не обещание неизменности будущих переводов.

Состав карт сопоставлен с [перечнем карт](https://huntshowdown.wiki.gg/wiki/Maps).
Для новой карты также использован
[официальный анонс Mammon's Gulch](https://www.huntshowdown.com/news/introducing-hunt-showdown-1896-welcome-to-colorado).
Написание берётся из клиента: внешние списки могут использовать варианты вроде
`Preston Oil Field`, тогда как клиентский баннер содержит `Preston Oil`.

| Код клиента | Ключ имени карты | Локаций |
| --- | --- | --- |
| `cemetery` | `ui_map_name_cemetery` | 16 |
| `civilwar` | `ui_map_name_civilwar` | 16 |
| `creek` | `ui_map_name_creek` | 16 |
| `colorado` | `ui_map_name_colorado` | 16 |

Названия карт взяты из `text_ui_menus.xml` (первые три) и `text_ui_ingame.xml`
(`colorado`). Локации взяты из `text_ui_ingame.xml`, ключи
`ui_missionarea_banner_{code}_{mapCode}`. Для каждой карты это `com_a`...`com_m`
и `poi_a`...`poi_c`. Используется локализованная колонка XML Spreadsheet,
а не соседняя английская исходная строка. Баннерные ключи содержат цельные названия
без принудительных переносов, встречающихся в подписях карты.

Регистр, апострофы, кавычки и орфография сохранены как в клиенте. Например,
`Де-Салль`, украинское `ДЮСЕЛЬ` и польское `DESALLE` не приводятся к общей форме.
Учебные карты, стрельбище и дубли ключей в верхнем регистре не являются отдельными
картами или локациями справочника.

Миграционные тесты проверяют полный набор названий по контрольной сумме,
покрытие четырёх локалей, принадлежность локаций картам, ограничения БД,
повторное применение и откат с повторным обновлением. Для воспроизведения сверки
извлеките указанные таблицы из этих PAK и сопоставьте по ключам выше. Строки для
контрольной суммы: `{mapCode}|{locationCode или map}|{locale}|{name}`, сортировка
Ordinal, UTF-8 без BOM, LF после каждой строки, включая последнюю.
