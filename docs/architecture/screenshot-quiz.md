# Викторина по скриншотам

Скриншот является форматом обычного вопроса. Он использует те же игровые сессии,
ответы, журнал начислений и баланс. Участник отвечает один раз через сайт или
Twitch; второй канал не создаёт ещё один ответ. Общий лидерборд сохраняет прежний
порядок ранжирования. Статистика игры дополнительно разделяет попытки, правильные
ответы и заработанные очки по текстовым вопросам и скриншотам.

Оба формата используют метки `!1`, `!2` и далее на сайте, в истории, оверлее и
сообщениях Twitch. Номер соответствует позиции в сохранённом сервером порядке
вариантов текущего вопроса. Клиенты не сортируют ответы заново и не перемещают
правильный ответ в начало; перевод названия локации не меняет её номер.

## Каталог

Управление находится на отдельной странице `/panel/catalog-screenshots` в разделе
каталогов. Каталог вопросов показывает только текстовые вопросы. В каталоге
скриншотов ведущий выбирает карту, локацию, категорию и награду, затем добавляет
несколько изображений. Каждый файл создаёт отдельный вопрос. Сервер выбирает пять
других локаций той же карты и сохраняет шесть вариантов с переводами на `en`, `ru`,
`uk`, `pl`. Источник названий описан в [справочнике Hunt](hunt-location-catalog.md).
В Twitch используются русские названия, как в существующей текстовой викторине.

Поддерживаются JPEG, PNG, GIF и WebP до 5 МиБ. Проверяются размер, MIME и сигнатура.
`POST /api/game/questions/screenshots` принимает один файл и UUID запроса.
Обязательный текст вопроса (до 2000 символов) задаётся для всего пакета и
сохраняется у каждого изображения. Сайт, OBS, Twitch и история используют
сохранённый текст без подстановки шаблонной фразы.
Пакет загружается последовательно с отдельным статусом каждого файла. Повтор
использует исходный UUID и параметры: сервер возвращает уже созданный вопрос,
а при несовпадающем содержимом возвращает конфликт. До завершения попыток
параметры пакета заблокированы. Успешные файлы повторно не отправляются.

`question_screenshots` связывает вопрос, локацию и `media_assets`. Объект получает
случайный ключ без имени локации. Снимок изображения и вариантов неизменяем.
Сайт и OBS получают прямой URL публичного хранилища, как для изображений карточек.
В снимке сохраняется путь объекта; адрес хранилища берётся из текущей конфигурации.
Анонимные API каталога для выдачи файлов не требуются.
Текст вопроса, категорию, награду, приоритет и доступность можно менять через отдельный редактор
скриншота. Он сохраняет исходный порядок и содержание вариантов ответа.
Для замены изображения или правильного ответа создаётся новый вопрос, старый
отключается. Файл сохраняется для истории даже после удаления вопроса из каталога.
Поиск в каталоге и настройке игры учитывает карту, варианты локаций на выбранном
языке и код вопроса. Миниатюры вне видимой области загружаются при прокрутке.

## Запуск и исключение конфликтов

Настройка игры отдельно задаёт время ответа на скриншот, по умолчанию 60 секунд.
В управление викториной входят два блока: текстовые вопросы и скриншоты.
У каждого есть автоматический запуск следующего и выбор конкретного вопроса.
Вопросы включаются в игру через существующую настройку каталога.

Автоматический выбор общий для сайта и Twitch: минимальное число использований
в прошлых игровых сессиях, затем максимальный приоритет, затем случайный выбор
среди равных. Конкретный вопрос используется один раз за игру. Несколько
скриншотов одной локации являются независимыми вопросами и могут идти подряд.
При запуске варианты перемешиваются один раз; сайт, чат и OBS используют этот
сохранённый порядок и номера `!1`...`!6`.

Открытая сессия, подготовка публикации в Twitch и заказ модификаторов взаимно
блокируются под блокировкой строки игры. Публикация Twitch резервирует запуск до
подтверждения или отмены; после отправки вопроса и вариантов открывается сессия
с тем же изображением, порядком ответов и длительностью.

## OBS, результат и история

`game_quiz_presentations` хранит отображаемую сессию отдельно от её результата.
Скриншот имеет приоритет над фазой игры, лидербордом и тестовой сценой OBS.
Фоновые игровые таймеры продолжают работать. По окончании времени сервер
закрывает приём ответов, начисляет очки и раскрывает правильный вариант.
Правильный ответ отсутствует в публичной проекции открытой сессии.

Результат остаётся на экране до команды «Скрыть скриншот» или запуска следующего
вопроса. Пока изображение отображается, заказ модификаторов заблокирован.
Скрытие требует закрытой сессии и её ожидаемого идентификатора: запоздалый запрос
не может скрыть следующий скриншот. Повторное скрытие уже убранного результата
безопасно. После скрытия OBS восстанавливает актуальную основную сцену.

Снимок изображения и всех переводов копируется из каталога в настройку игры,
публикацию Twitch и игровую сессию. Изменение справочника или настроек каталога
не переписывает прошлые результаты. История показывает изображение, варианты,
ответы участников и награды; доступен фильтр по формату. Общие очки, ручные
начисления и траты сохраняют прежний смысл.

Миграция `20261102190414_AddScreenshotQuiz` добавляет связи, снимки и ограничения
неизменяемости. `20261102195810_HardenScreenshotOptionIntegrity` дополнительно
проверяет соответствие шести вариантов сохранённому снимку при добавлении
или переносе вариантов между вопросами. HTTP и realtime контракты определены в
[`deadmans.v1.yaml`](../../backend/openapi/deadmans.v1.yaml).
